## 1. Project Objective & Overview

**CampusNet Monitor** is a full-stack, demonstration-ready network simulation and operations dashboard designed to model campus-wide computer network traffic, detect bottleneck link congestion, and evaluate traffic-control algorithms.

The project models:
- **Hierarchical Network Topologies:** Core Router, Core Switch, Department Switches (CSE, ECE, Administration, Library), Student Wi-Fi AP, and connected host workstations.
- **Bandwidth Utilization & Queuing:** Real-time calculation of offered load, admitted transmission, buffer occupancy, and packet drops under link bottlenecks.
- **Congestion Detection Engine:** Threshold detection (Normal < 70%, Warning 70–85%, Critical ≥ 85%) equipped with a **hysteresis persistence window** to eliminate alert flapping.
- **Active Traffic Control Algorithms:** Fully executable Python implementations of **Leaky Bucket (traffic shaping)** and **Token Bucket (burst control & policing)**.
- **Quality of Service (QoS):** Multi-class packet scheduling comparing **First-In-First-Out (FIFO Drop-Tail)** against **Strict Priority Queuing (PQ)** across Voice/Video, Web, and Bulk File Transfers.
- **Automated 1-Click Before-and-After Experiments:** Mathematically fair benchmarks using identical initial random seeds, computing delivered throughput, latency, loss, and queue reductions with CSV and printable HTML export.

> **Academic Disclaimer:** This is an academic simulation prototype. It does not monitor or alter physical network devices of the campus network. All telemetry is generated by a deterministic local simulation engine.

## 5. Network Algorithms Explained

### A. Leaky Bucket Algorithm (`traffic_controller.py`)
- **Concept:** Incoming packet arrivals enter a finite buffer of capacity $C_{\text{leak}}$.
- **Behavior:** Regardless of input burstiness, packets drain out at a strictly uniform rate $R_{\text{leak}}$.
- **Overflow:** If an arriving burst exceeds the unallocated buffer room ($C_{\text{leak}} - \text{current\_fill}$), the excess packets are dropped.
- **Academic Demonstration:** Shows traffic smoothing and how finite buffers convert burst spikes into queueing delay rather than downstream link collapse.

### B. Token Bucket Algorithm (`traffic_controller.py`)
- **Concept:** Tokens are continuously generated at rate $r$ into a bucket of capacity $B$.
- **Burst Allowance:** If traffic has been idle, tokens accumulate up to $B$. A burst up to $B$ is transmitted instantaneously without queuing delay.
- **Dual Enforcement Modes:**
  - `shaping`: Packets that exceed available tokens wait in a buffer until new tokens arrive.
  - `policing`: Packets exceeding available tokens are immediately dropped (drop non-conforming).

### C. Quality of Service (QoS) Priority Queuing (`qos_scheduler.py`)
- **Classes:**
  1. High Priority (Voice / Video-Conferencing): DSCP EF (46)
  2. Medium Priority (Interactive Web Browsing): DSCP AF21 (18)
  3. Low Priority (Bulk File Transfers / Backups): Best Effort
- **Comparison:**
  - **FIFO (Drop-Tail):** All traffic shares one buffer. When congested, packet drops hit all flows equally, degrading video calls and web loading alike.
  - **Strict Priority Queuing (PQ):** High-priority packets are admitted and transmitted first. Voice/Video achieves ~0% drop rate and low latency, while bulk downloads absorb necessary delays and drops.

### D. Congestion Detection & Hysteresis (`congestion_detector.py`)
- **Thresholds:** Configurable in Settings (Default: Warning 70%, Critical 85%).
- **Multi-metric Diagnosis:** Rather than looking only at utilization, the engine verifies queue occupancy, queue growth, and packet drops.
- **Hysteresis Window:** Requires the condition to persist for $N$ consecutive monitoring intervals (default 2) before elevating or clearing alert states, avoiding transient alert flapping.

## 6. Demonstration Scenarios for Academic Evaluation

Follow these 8 steps during an examination or course demonstration:

### Scenario 1: Normal Network Operation
1. Open the **Overview Dashboard**.
2. Notice the normal campus state (~45 Mbps offered, ~0% packet drops, low latency ~3–5 ms).
3. Check the **Protocol Breakdown** chart showing simulated TCP (65%), UDP (25%), ICMP (5%).

### Scenario 2: Sudden Traffic Surge / Congestion
1. Navigate to **Live Traffic Monitoring**.
2. Under "Select Active Traffic Profile", choose **Registration Burst Crowd** (220 Mbps spike).
3. Alternatively, use **Stress Test Link (Surge)** to inject a 2.5x traffic surge on `SW_CORE ↔ SW_CSE`.
4. Observe the link utilization jump to >90% and queue buffers start accumulating packets.

### Scenario 3: Congestion Detection & Alerts
1. Navigate to **Congestion Alerts**.
2. Observe the automated alert created with severity **CRITICAL** on the saturated link.
3. Note the diagnosis: *"Queue buffer overflow under offered demand"*.
4. Click **Acknowledge** on the alert to log NOC engineer review.

### Scenario 4: Leaky Bucket Traffic Control
1. Navigate to **Traffic Control (QoS)**.
2. Select **Leaky Bucket Traffic Shaping** and click **Activate Leaky Bucket**.
3. Watch the visual buffer fill gauge fluctuate smoothly and observe output rate stabilized at the configured leak rate (35 Mbps).

### Scenario 5: Token Bucket Burst Control
1. Under **Traffic Control (QoS)**, tune Token Bucket to `shaping` or `policing`.
2. Click **Activate Token Bucket**.
3. Observe tokens replenish up to burst capacity and burst count counter incrementing.

### Scenario 6: Quality of Service (QoS) Scheduling
1. Under **Traffic Control (QoS)**, switch the policy to **Strict Priority Queuing**.
2. Compare the per-class breakdown: Voice/Video maintains 0% packet loss, while Bulk Transfers absorb queue buffer delay.

### Scenario 7: One-Click Before-and-After Experiment
1. Navigate to **Performance Comparison**.
2. Choose Workload Profile: **Registration Burst Crowd**, Algorithm: **Leaky Bucket**, Duration: **20 ticks**.
3. Click **Run Automated Before-and-After Experiment**.
4. The system automatically executes:
   - Phase 1: Baseline run without control.
   - Phase 2: Controlled run under the identical seed.
5. Review the side-by-side comparison cards, bar charts, and mathematical delta table (throughput, latency, loss change).

### Scenario 8: Exporting Reports & SQLite History
1. In **Performance Comparison**, click **Export CSV** to download `campusnet_experiment_comparison.csv`.
2. Click **Printable Report** to open a print-ready HTML evaluation report.
3. Open **Experiment History** to verify the run has been persisted into SQLite and remains accessible after server restarts.

## 7. Network Architecture & Protocol Specifications

| Layer / Subsystem | Network Protocol | CampusNet Monitor Implementation |
|---|---|---|
| **Topology & Backbone** | IEEE 802.3, 802.1Q | Hierarchical campus tree topology connecting Core, Block Distribution (A, B, C, D, E, PG, Wi-Fi), and Access layers. |
| **Queuing & Buffer Telemetry** | FIFO Buffer Management | Time-stepped discrete buffer modeling with finite queue lengths (`max_queue_packets`) and queue occupancy percentages. |
| **VLAN Segmentation** | 802.1Q Subnets & Trunks | Block A (VLAN 100), Block B (VLAN 200), Block C (VLAN 300), Block D (VLAN 400), Block E (VLAN 500), PG (VLAN 600), Wi-Fi (VLAN 700). |
| **Traffic Control & Shaping** | Leaky & Token Bucket | Mathematical Python implementations of Leaky Bucket smoothing, Token Bucket burst regulation, and Multi-Class Priority Queuing. |
| **Telemetry & Protocols** | TCP, UDP, ICMP | Real-time monitoring of TCP/UDP/ICMP traffic shares, throughput time-series graphs, and CSV telemetry exports. |

## 8. Automated Testing

The project includes an automated test suite verifying all algorithms, edge cases, and API routes.

Run the test suite:
```powershell
python -m pytest tests/test_all.py -v
```

### Verified Test Cases (18 Passed):
- `test_leaky_bucket_normal_and_smoothing`: Verifies constant output leak and buffer drain.
- `test_leaky_bucket_overflow_drop`: Confirms drops occur when arrivals exceed buffer capacity.
- `test_leaky_bucket_zero_and_empty_traffic`: Verifies zero division safety and empty buffer states.
- `test_token_bucket_burst_allowance`: Verifies bursts pass instantaneously when tokens are present.
- `test_token_bucket_policing_drop`: Validates immediate packet drop in policing mode.
- `test_token_bucket_shaping_buffer`: Confirms packets buffer and wait for tokens in shaping mode.
- `test_fifo_drops_shared_equally`: Confirms drop-tail tail drops hit all traffic classes indiscriminately.
- `test_priority_protects_high_class`: Verifies Strict Priority Queuing guarantees 0 drops for high priority.
- `test_threshold_classification`: Validates Normal, Warning, and Critical boundary triggers.
- `test_hysteresis_persistence_window`: Verifies persistence window suppresses 1-cycle alert flapping.
- `test_simulator_lifecycle`: Tests start, step, pause, resume, and reset.
- `test_topology_capacity_update_and_validation`: Tests link bandwidth modification and validation.
- `test_topology_add_and_remove_host`: Verifies host additions and deletions.
- `test_experiment_consistency`: Verifies baseline vs controlled reproducibility and delta metrics.
- `test_exports_generate_valid_csv`: Verifies CSV formatting for metrics, alerts, and experiments.
- `test_api_dashboard`, `test_api_topology`, `test_api_settings_validation`: REST API sanity tests.

1. In the Render Dashboard, click **New +** > **Web Service**.

3. Fill in the following fields:
